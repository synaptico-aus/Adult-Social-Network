| Google privacy | Complete Data safety from actual first/third-party collection, including controlled webviews. A processor is not automatically an exempt transfer; verify contractual conditions. | Apple deletion | Initiate deletion in app; deactivation alone is insufficient. Explain reasonable completion time and justified retention. If Apple login is used, revoke applicable Apple tokens. Email-only deletion is generally not acceptable for ordinary social apps. | https://developer.apple.com/support/offering-account-deletion-in-your-app/ |
| Google deletion | In-app deletion route plus a functional external web request resource, including for people who uninstalled. Delete associated data and request processor erasure; disclose justified exceptions. An FAQ/home page with no request path is insufficient. | https://support.google.com/googleplay/android-developer/answer/13327111?hl=en |
| Apple sign-in | Guideline 4.8 applies when a third-party/social service authenticates the primary account, subject to listed exceptions. An equivalent option must limit name/email collection, allow private email and not collect advertising interactions without consent. Assess actual configured providers. First-party email/password only is a listed exception; using Clerk alone does not prove Google login or compliance. If applicable, implement and test Sign in with Apple and token revocation rather than assuming an ordinary email form qualifies. | https://developer.apple.com/app-store/review/guidelines/ |
| SDKs | Inspect the actual archive, SDK privacy manifests/signatures where required, approved required-reason API uses and transitive native dependencies. Web package inventory is not an iOS privacy manifest or final Android declaration. No native artifact exists yet. | https://developer.apple.com/documentation/bundleresources/privacy-manifest-files and https://developer.apple.com/support/third-party-SDK-requirements/ |
| Apple ratings | Complete the current questionnaire honestly: UGC, messaging, medical/health topics, age assurance, parental controls, web/content access and actual content frequency. Apple calculates ratings; newer OS categories and regional/older-OS ratings can differ. Do not translate Me's 18+ membership policy into an invented store rating. | https://developer.apple.com/help/app-store-connect/reference/age-ratings-values-and-definitions/ |
| Google ratings/health | Complete IARC content rating and target-audience answers for actual features. The Health apps declaration is required for all apps on closed/open/production tracks, even those declaring no health features. Do not claim clinical approval, efficacy or child eligibility. | https://support.google.com/googleplay/android-developer/answer/9859655?hl=en and https://support.google.com/googleplay/android-developer/answer/14738291?hl=en |
| Apple submission tools | Since 28 April 2026, Xcode 26+ and the iOS 26+ SDK for iOS uploads. This is a build-SDK requirement, not a claim that only iOS 26 devices may run Me. Verify deployment target separately. | https://developer.apple.com/news/upcoming-requirements/?id=04282026a |
| Google target SDK | Since 31 August 2026, new phone/tablet apps and updates target Android 16/API 36+. Other device families and existing-app visibility have different rules. Do not apply older API 35 new-app guidance. | https://support.google.com/googleplay/android-developer/answer/11926878?hl=en |
| Review access/backend | Full review access, accurate metadata, live backend and contact details required. A closed onboarding screen cannot stand in for reviewer access. | Accurate images | Capture the actual release candidate on the claimed device family; use fictional labelled accounts and no private health details. Apple's device-specific dimensions and Play asset rules must be checked at capture time. Never upscale a web preview and label it a native capture. | https://developer.apple.com/help/app-store-connect/reference/app-information/screenshot-specifications/ and https://support.google.com/googleplay/android-developer/answer/1078870?hl=en |
